## Outcome

Deliver one portable Knowledge Crew Controller for employee onboarding and daily work support. It must assemble a compact role-safe perception packet from reviewed memory and bounded retrieval; select responsibilities adaptively; control state and repair through LangGraph; express role/task contracts through CrewAI; validate every candidate action against current requirements; and preserve evidence, receipts, and reviewed promotion in WikiLLM/Obsidian without confusing any framework with authority.

The dashboard becomes the primary non-technical local interface for orientation, tasks, research, role work, review, receipts, knowledge maintenance, and configuration. Jarvis becomes an embedded operator assistant inside the case workflow rather than a competing standalone brain.

## Acceptance criteria

1. One case/state spine replaces Architecture 1/2 and any competing knowledge-store framing.
2. Role agents have Ukrainian call names written in English letters, stable machine IDs, responsibilities, inputs, outputs, skills, permission boundaries, and reviewer routes.
3. LlamaIndex, TurboVec, WikiLLM, Obsidian, Orbit/Graphify, CrewAI, LangGraph, and the dashboard have explicit non-overlapping jobs and truthful proof states.
4. The perception packet combines stable CAG, bounded source-grounded retrieval, role memory, exact-source reads, requirement checks, and an optional TurboVec candidate with lexical fallback and benchmark gates.
5. Research, market/pain analysis, PRD, qualification, outreach copy, publication creative, design, implementation, reporting, onboarding, task driving, review, and knowledge maintenance remain available as adaptive roles in one workflow.
6. Skill lifecycle is explicit: discover, inspect, deduplicate, scan, normalize, test, allowlist, assign, observe, update, deprecate, and rollback. Skill Spectre evidence is represented accurately; no unavailable semantic scan is claimed.
7. Four source-controlled diagrams explain general architecture, input/context flow, output/receipt flow, and onboarding/team collaboration. The tower diagram uses larger inter-layer gaps, exact text between layers, left knowledge/database callouts, and right output/delivery callouts.
8. The dashboard is self-contained, browser-local by default, responsive at mobile/tablet/desktop widths, keyboard operable, fully wrapped/aligned, and clear about configuration versus execution.
9. Dashboard configuration can be exported/imported as a public-safe review packet and documents how an approved local bridge can be connected without exposing secrets in the browser.
10. Deterministic validators, schema fixtures, dashboard smoke tests, visual screenshots, accessibility checks, public-safety checks, and independent review pass or leave explicit gaps.
11. Git staging includes only this isolated branch's intended changes, and the owner-authorized GitHub push is verified by remote commit hash.
