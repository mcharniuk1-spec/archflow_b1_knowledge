# Responsive Knowledge Crew And Crew Desk

Date: 2026-08-05
Status: independent review APPROVE; Git release pending staged checks

## Task

Unify ArchFlow around one role-responsive Knowledge Case for employee onboarding, daily task guidance, research, specialist work, validation, reporting, and maintained knowledge. Make the Crew Desk the primary non-technical local interface, publish exact framework boundaries and parameters, replace the separate Jarvis surface with contextual guidance, and preserve public/private safety.

## FACT

- The canonical configuration contains seven accountable layers, 21 schema-v3 roles with Ukrainian call names written in English letters, ten adaptive workflow packs, eight materialized onboarding role-task bindings, and a 12,000-token bounded perception budget.
- LlamaIndex owns allowlisted document/node retrieval and source return. TurboVec is an optional 4-bit candidate behind that adapter with lexical fallback and a 20-query promotion gate.
- WikiLLM is reviewed portable memory; Obsidian is optional private human context; Orbit/Graphify provide structure; CrewAI describes roles and tasks; LangGraph owns typed transitions, reducers, interrupts, repair bounds, and terminal receipts.
- Four editable labeled diagrams cover architecture, context input, output/receipts, and onboarding/teamwork.
- The six-route Crew Desk is browser-local, responsive, keyboard-operable, and supports validated configuration import/export without activating a provider or bridge.
- Core, adversarial, route, responsive, accessibility, interaction, JSON, YAML/Pydantic, SVG, image, link, public-safety, and clean-clone push-guard checks pass.
- Admission uses one namespaced policy envelope projected onto the canonical 27-state Knowledge Case registry; role-task authority is the intersection of case authority, role ceiling, runtime capability, exact targets, and explicit denials.
- The release-scope guard admits all 80 final candidate paths from the context capsule, rejects an unadmitted-path probe, and the capsule validates against its public schema.
- Every materialized role binding carries typed `GAP-*` references; fixed handoff payload names must resolve to binding fields, and an unknown-field negative fixture fails closed.
- CrewAI's required task fields are derived from and equal all 22 canonical binding-schema fields; the API manual's full Taras example validates and has a closed payload.
- The dashboard passed 24 route/viewport checks; the landing tower passed 28 layer/viewport checks.
- The inherited optional local LangGraph environment stalled in the LangSmith dependency import chain and was interrupted after the bounded wait. A prior LlamaIndex import also exceeded its bounded check. Neither is claimed as runtime proof; no provider call, trace, checkpoint, or writeback occurred.

## INTERPRETATION

The project no longer needs separate PRD and agent-control architectures. Requirements, market/pain research, outreach, copy, design, implementation, reporting, and knowledge maintenance are responsibility packs inside one evidence-preserving case. Framework selection can change without changing authority: people and reviewed source/requirement records remain accountable, while tools provide retrieval, structure, coordination, state control, or projection.

## HYPOTHESIS

Mission-first onboarding and explicit role/reviewer handoffs should shorten time to a first valid employee output and reduce manager repair. A representative employee pilot is still needed. TurboVec may improve compact local perception, but the existing small synthetic trial does not justify default promotion.
